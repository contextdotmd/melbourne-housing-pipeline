# Surrogate keys via `dbt_utils.generate_surrogate_key`

Composite keys — `property_key` (suburb + street address) and `listing_outcome_key` (business
signature + event date) — are MD5 hashes over separator-joined, null-sentinelled column
values, generated by `dbt_utils.generate_surrogate_key` rather than hand-rolled SQL.
Single-column dimension keys stay natural: the lowercased entity name or the source code.

## Consequences

This avoids the two failure modes of an ad-hoc `hash()` approach: engine hash functions are not
guaranteed stable across versions, and concatenating without a separator makes `('ab', 'c')`
collide with `('a', 'bc')`. It is also portable, which matters given ADR-0001's porting story.
